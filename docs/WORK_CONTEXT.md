# Контекст работы — 2026-11-08

Снимок для продолжения в другой сессии. Перед действиями сверить ветку, status и log с Git.

## Цель и решения

Сравнить manual DI, Hilt, Koin и Metro в одном Android-приложении с Navigation 3, сохранив поведение.
Выбраны отдельные Git-ветки вместо копий проекта. Переключение DI в одной сборке не создаём.
Внедрены Metro, затем Koin с Classic DSL без compiler plugin, затем manual DI в main
по явному запросу пользователя. Сначала документация синхронизирована во всех ветках,
после этого main переведён с Hilt на manual DI.

Шесть [схем навигации](navigation.md) охватывают команды, middleware, deep links, результаты,
восстановление и независимые разделы.
Архитектура DI: [атлас DI](di/README.md), [Manual](di/manual.md), [Hilt](di/hilt.md), [Metro](di/metro.md), [Koin](di/koin.md).
Обзор и команды: [README](../README.md). Правила: [AGENTS](../AGENTS.md).

## Сценарий 1

- Home переиспользует публичный Feed. Requests состоит из защищённых списка и карточки с локальными данными.
- Навигатор хранит обе истории и выбор отдельно. Каждый стек декорируется независимо, поэтому переход
  между разделами сохраняет состояние и ViewModel записей. Login возобновляет исходный выбор раздела.
- Logout возвращает к Feed и очищает Requests. Сессия остаётся в памяти процесса. При восстановлении без
  неё доступен только публичный префикс Home, даже если Bundle содержит закрытые ключи.
