# NavPlayground

Перед изменениями прочитайте `docs/WORK_CONTEXT.md` и `README.md`.
Проверьте текущую ветку и рабочую директорию: сохранённый контекст — снимок, а не живое состояние Git.
При работе с навигацией прочитайте `docs/navigation.md`; при изменении логики обновите соответствующие схемы.
При работе с DI прочитайте `docs/di/README.md` и схему соответствующей реализации.

## Правила проекта

- Это учебный многомодульный Android-проект для сравнения manual DI, Hilt, Koin и Metro.
- Реализации DI разделены по веткам: `main` — manual, `di/hilt` — Hilt, `di/koin` — Koin,
  `di/metro` — Metro. Работайте в соответствующей ветке и не смешивайте DI-миграции.
- Фичи зависят от своего/чужих `api` и `core`, но не от чужих `impl`.
  Только `app` собирает все реализации фич.
- Сохраняйте поведение навигации, общие экземпляры навигатора/сессии и ViewModel на запись бэкстека.
- Не коммитьте `local.properties`, кеши, результаты сборки и настройки IDE.
- Проверка изменений DI: `./gradlew :app:assembleDebug testDebugUnitTest --console=plain`
  (PowerShell: `.\gradlew.bat :app:assembleDebug testDebugUnitTest --console=plain`).
- При завершении существенного этапа обновляйте `docs/WORK_CONTEXT.md`: результаты, проверки,
  ограничения и оставшуюся работу. Не записывайте секреты или личные данные.
- Подробное описание DI и схемы храните в `docs/di/`, обзор и запуск — в README,
  состояние работы — в WORK_CONTEXT. Используйте ссылки вместо повторения описаний.
- При изменении графа, вкладов фич, factory или времени жизни объектов актуализируйте соответствующую
  Mermaid-схему и сравнение в `docs/di/README.md`. Помечайте планируемые решения как план;
  название ветки само по себе не подтверждает наличие реализации.
- Общая документация есть в `main`, `di/hilt`, `di/koin` и `di/metro`; корневой README описывает текущую ветку.
  При смене ветки проверяйте статус по `docs/WORK_CONTEXT.md`, `git log` и исходникам.
  Новую DI-реализацию не переносите в другую ветку вместе с документацией.
  Общие изменения AGENTS, WORK_CONTEXT, docs/navigation.md и docs/di синхронизируйте во всех четырёх ветках.
- В main manual DI уже внедрён: AppContainer — composition root, core:di — фабрика ViewModel
  и Compose helper. Новую фичу нужно явно добавить в коллекции и карту фабрик AppContainer.
- Koin-вклады одного интерфейса должны иметь уникальные qualifiers: используется `allowOverride(false)`.
  Не регистрируйте разные generic Set без qualifiers; собирайте вклады через `getAll<T>()` у потребителя.
